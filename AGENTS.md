# Valheim mod workspace

- Follow the Single Responsibility Principle for game modes and features: create a separate plugin project for each new mode. Add it to `ValheimMods.sln` rather than adding unrelated behavior to an existing plugin.
- When adding a new plugin, do not modify existing plugin projects or their code, assets, or package metadata unless the user explicitly requests it. Limit changes to the new plugin and shared workspace files needed to integrate it.
- Publish or upload plugin packages only when the user explicitly requests publishing and gives consent for the specific release. Do not infer publishing consent from requests to create, build, package, or prepare a release. Without that explicit consent, prepare local artifacts only and do not run publishing commands or create remote releases.
- This solution builds Valheim BepInEx plugins. Running them requires [Gale](https://github.com/Kesomannen/gale) with the [Valheim BepInEx pack](https://thunderstore.io/c/valheim/p/denikson/BepInExPack_Valheim/) installed in the selected Gale Valheim profile. The user's current installation is in the `Default` profile under `%APPDATA%\com.kesomannen.gale\valheim\profiles\Default`. Launch Valheim with **Start modded** in Gale to load the plugins.
- Each plugin project must set `<IsValheimPlugin>true</IsValheimPlugin>`. Builds and packaging must copy nothing to `BepInEx\plugins` by default. The shared `Directory.Build.targets` copies DLLs only for project names explicitly selected with `ValheimPluginsToCopy`; never select mods on the user's behalf.
- After a successful build, ask the user which mods should be copied to the local profile and wait for their explicit selection before copying. A request to create, fix, build, or package a mod is not permission to copy it. If the user already explicitly named mods to copy in the current request, copy only those mods without asking again. Use `copy-mods.ps1 -Plugin <requested project names>` to copy an existing build. After copying, verify the requested DLLs in the destination and show the user the full path to the local `BepInEx\plugins` folder as a clickable link.
- The destination can be changed with the MSBuild property `ValheimPluginsPath`; the Gale profile can be changed with `GaleProfile`. Do not assume BepInEx is installed in the Steam game directory.
- Reference BepInEx from the Gale profile and Unity assemblies from the Valheim game directory. Do not copy BepInEx or Unity runtime assemblies into the plugins folder.
- Each plugin project's `README.md` is packaged as that plugin's public Thunderstore page. Keep player installation instructions, including manual ZIP installation, in those plugin READMEs. Use the repository root `README.md` for source, build, and workspace guidance. For manual ZIP installation, tell players to install the Valheim BepInEx pack, extract the ZIP, place the extracted folder containing the plugin DLL under the active profile's `BepInEx/plugins`, and remove duplicate copies of the DLL.
- Give every plugin project its own distinct 256 x 256 PNG at `ValheimMods/<Plugin>/icon.png`. Package that file as `icon.png` in the plugin's ZIP, and point its Thunderstore publisher configuration to the same project icon. Do not use a shared icon for multiple plugins.
- Give every plugin project its own `ValheimMods/<Plugin>/CHANGELOG.md`, following [Thunderstore's changelog guidance](https://wiki.thunderstore.io/mods/updating-a-package#changelog). Package it at the ZIP root with the exact name `CHANGELOG.md`. Use `## v<version>` headings in newest-first order, including the current `manifest.json` version, and retain all earlier entries when creating a new version. Keep release history only in `CHANGELOG.md`; do not add a Changelog section or version history to plugin `README.md` files.
- Verify each plugin ZIP contains its own DLL, manifest, README, changelog, icon, and the root license. Leave changes uncommitted unless the user explicitly requests a commit.
- The repository and plugin packages use `GPL-3.0-only`. Keep the root `LICENSE` file in every release ZIP and identify the license in each plugin's public `README.md`.
- When changing build or deployment behavior, run `dotnet build ValheimMods\ValheimMods.sln` and verify that an ordinary build does not create or change files in the selected profile's `BepInEx\plugins` folder. Test selective copying against a temporary destination inside the workspace; copy to the user's actual profile only after they explicitly select mods, then verify the requested DLLs and show the full local folder path.
